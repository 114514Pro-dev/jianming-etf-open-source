# D0 网页控制台与 EMTL 适配边界

私有网页拟单默认不下单。另有默认关闭的[东方财富证券网页手动委托](emtl-web-manual.md)，与拟单路径完全分开。

## 已实现：私有网页拟单

仅在开发或私有实例的服务端设置 `ETF_D0_WEB_PREVIEW=1` 并重启，登录简明 ETF 后打开 `/d0-control`。默认不开启。页面查看原版 D0 的信号与行情状态，核对资金和可卖份额后计算拟单。不会写入纸上账本，也不会存储填写的数据；API 需要站点登录、同源请求和 CSRF 校验。不要把当前公开的临时演示实例当成真实账户控制台。

- `production/d0_order_preview.py` 同时供网页和 `scripts/emtl_d0.py preview` 使用。不接受浏览器提供的信号或报价；网页提交时由服务端重新读取。
- `production/bank_model.py`、`production/dynamic_allocation.py`、`production/d0_bank_gate.py` 保持原策略不变。沿用已确认 D0 的信号、日期、目标权重和 09:30 起执行的规则，不把模拟成交当成真实委托。
- 约 87 万元只是当前规模，不写入计算。若整户专供 D0，权益按本次的总现金与 D0 四只 ETF 的行情市值计算，无需给出固定本金。50% 权重对应 87 万权益的 43.5 万、90 万权益的 45 万；拟单按目标份额减去现有份额，不会再次买入全部目标金额。网页分别展示目标金额和整手拟单。遇到非 D0 持仓、其他策略或手工委托时，须先确认如何隔离；不能默认卖掉其他标的，或把其市值也变成买入额度。目标未配满时保留现金。

## D0 自动执行器的接线（尚未实现／验证）

核对 [EMTL 使用指南](https://emtl.readthedocs.io/zh-cn/latest/usage.html) 和 [API 参考](https://emtl.readthedocs.io/zh-cn/latest/reference/emtl.html)：`latest` 是开发文档，当前接线以已安装稳定版 `emtl==0.3.1` 为准。使用独立的 `TradingClient`，不使用旧的全局会话 API。

| D0 需要什么 | EMTL 接口及注意事项 |
| --- | --- |
| 可用现金、持仓、可卖数量 | `query_asset_and_position()` 返回券商原始 JSON；需用授权环境的脱敏样例确认资产、可用与冻结、可卖字段及版本。不能把空响应当作空仓。 |
| 已有委托、成交、卖出资金是否可用 | `query_orders()`、`query_trades()` 加重新查询资金。委托受理、部分成交、已撤销和整单成交是不同状态。 |
| 买卖请求 | `create_order(stock_code, trade_type, market, price, amount)`。从 D0 白名单的内部标识转换成六位证券代码、买卖方向和市场参数；份额仍按 D0 规则。EMTL 测试使用 `B`/`S` 和 `SA`，其他实现还使用 `HA`；这些属于接口线索，不是本账户的沪深 ETF 实盘验收。 |
| 撤单请求 | `cancel_order(order_str)` 的请求参数须由已核验的真实券商委托标识构造。返回文本不能当作已经撤单。 |
| 委托状态不明 | `TradeOutcomeUnknown` 时先停住该信号，查委托和成交并人工核对。严禁把超时当失败并原样重发。即便普通返回 JSON，也须按券商字段确认为受理，不能当成交。 |

线上建议是**私有 HTTPS 网页控制台 + 独立券商执行进程**。网页仅发送已确认操作并查看审计状态。券商凭证只由执行进程从云端安全存储读取，不进入简明 ETF 普通站点、浏览器、日志或聊天。云环境准备好前，用合成账户和响应检查代码行为。

启用真实委托前至少需要：单一执行器；显式授权开启/暂停自动运行；绑定账户、信号和订单参数；持久化委托意图和去重；超时停机与对账；单笔/单日资金上限；紧急停止；专用登录和 MFA。目标模式是由用户在私有网页启用，之后系统按验证过的 D0 信号自动买卖，而不是逐笔弹窗确认。当前没有实现该模式。F0、L0、F5 待后续独立分账后再接。

核对本地代码发现以下执行差异需要在实盘前解决：模拟服务固定同一计划的目标份额，而网页拟单每次按最新快照重算；执行器需要固定每轮已记录目标，不能把连续重算当作新委托。当前预览对卖出剩余不足一手的情况也会阻止进入买入阶段；不能在未验证券商零股卖出规则时静默放行。未成交不继续买，预期卖出款不计入可用现金。交易日历目前只覆盖到 2026-12-31。发单速度分别记录「生成委托到券商确认受理」和「受理到首笔、全部成交」，查询耗时、HTTP 超时值都不能替代它们。
