# D0 本机连接器：只读验收版与后续验收门槛

## 当前可用：Windows 本机只读验收

`desktop/d0_connector` 是源码试验版，不是生产量化客户端。需 Windows x64、python.org 的 Python 3.13 x64（含 Tcl/Tk 和 `py` 启动器）。从本仓库下载源代码，解压后在该目录双击 `launch.cmd`。它在目录内创建虚拟环境，按 Windows 专用哈希锁安装 `EMTL 0.3.1`，再打开验收窗口。不要运行来路不明的同名安装包。

在本机窗口输入**本人获授权的**资金账号和交易密码。应用直接联系券商，只调用登录、查询资金／持仓、查询当日委托，然后断开；不会保存密码或 token，也不会上传任何查询结果到简明 ETF 网站。验收窗口只显示尾号和只读摘要。如果显示成功，请自行与东方财富官方客户端核对，不要发送密码、令牌、账号全号或资金截图。只反馈「只读核对成功／失败」或显示的简短错误即可。

Windows 已验证锁定安装和实际 EMTL 模块导入；仓库中的流程测试使用合成响应。发行方没有提供 Windows 真账户的验收证据。登录、资金/持仓和委托字段均需在实际账号上核对，未知格式会明确阻止后续操作。只读通过也不是报单或成交验收。

## 下一阶段：设备绑定及自动执行（未实现）

- **浏览器不读取磁盘上的券商凭据。** 网站和本机应用用短期挑战做配对：应用在 Windows 用户凭据保护下保存专属设备私钥，网站只登记公钥及设备状态。挑战须绑定网站会话、设备公钥、随机值和过期时间，并且只消费一次；通过已登录网页明确核对配对码、撤销设备。私钥、交易密码及券商 cookie/validate key 永远不进网站。EMTL 不提供可公开支持的跨进程恢复会话接口，不应靠序列化内部属性绕过重新登录。设备身份不会替代券商认证。
- **交易口令和两次确认都在应用里。** 第一次展示并确认 D0、授权账户尾号、仅四只 ETF、单笔/单日限额、启用期限与停机入口；第二次确认同一授权参数并重新输入交易密码，由券商实际验证。任何参数变更、会话过期或程序重启都结束授权，不在浏览器或网站上代为激活；不存储交易密码。
- **网站不直接指挥券商发单。** 网站可提供只读的 D0 已确认信号；客户端应核对信号真实性、到期时间、原始 D0 规则以及券商行情。以真实权益计算目标、用可卖数量先卖，等到实际成交及可用资金更新才买。每个信号周期须冻结目标、持久化每笔发单意图、幂等去重，并能在断网/重启后与券商对账。回执不等于成交；超时或不确定结果立即停止，无自动重发。
- **后续按阶段验收。** 先本人验证只读；再验设备配对与撤销、合成演练和系统停机；只有在映射和账户权限核实之后，用户才能选择批准极小金额的手动真实限价委托并在官方终端复核，之后才考虑开放有限时的自动 D0。安装包须有可验证的来源和校验，并明确使用者负责保管本机账户和访问权限。
