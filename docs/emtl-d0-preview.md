# D0 × EMTL：拟单与账户只读验收

这一阶段**不会提交或撤销任何真实委托**。工具分开读取两个来源：

- `preview` 从简明 ETF 已有的 D0 模拟盘接口拿确认信号和行情，使用你手工核实的 D0 资金、持仓和费用生成拟单。支持保存好的接口 JSON；不调用 EMTL，不读取模拟盘的现金或持仓来代替真实账户。没有复用东财掘金联调文件，也不调用另外授权的 `/api/live-trading/signal`。
- `probe` 用固定版本 `emtl==0.3.1` 登录东方财富证券，仅读取资金持仓、当日委托和当日成交。打印阶段、HTTP 查询耗时以及数据是对象还是数组，不打印金额、持仓、账号和会话令牌。**这一版不猜测东财账户字段，不会把探针响应自动当作算单输入。**

## 拟单：不需要券商账户

需要站点接入当天行情，有 D0 已确认信号，并在执行日连续交易时段（北京时间 09:30–11:30、13:00–14:57，结束时间不含）运行。当前仓库的交易日历覆盖到 **2026-12-31**；超出覆盖范围会拒绝拟单。关闭自动刷新、只用历史种子的演示站点不会产生可用实时拟单。

按你明确分给 D0 的资金和份额准备一个**不含账号和口令**的 `balances.json`，不要提交到 Git。下面数字是示例，`observed_at` 要替换成核对资金、持仓与未结委托时的真实北京时间；数据超过 60 秒会被拒绝。`cash` 是分给 D0 的总现金，不含 ETF 市值；`available_cash` 是其中目前可用于买入的部分。若曾有其他策略或手工委托，不要把它们的资产和可用资金误填进来。

```json
{
  "observed_at": "2026-11-24T09:30:00+08:00",
  "cash": "10000.00",
  "available_cash": "10000.00",
  "pending_orders": false,
  "commission_rate": "0.0003",
  "min_fee": "5.00",
  "positions": {
    "sz159915": {"held": 0, "sellable": 0},
    "sh512800": {"held": 0, "sellable": 0},
    "sh518880": {"held": 0, "sellable": 0},
    "sh511010": {"held": 0, "sellable": 0}
  }
}
```

```powershell
python scripts/emtl_d0.py preview --site https://your-etf.example --balances balances.json
# 或读已保存的 GET /api/realtime-paper?strategy=D0 JSON：
python scripts/emtl_d0.py preview --snapshot d0-snapshot.json --balances balances.json
```

`--site` 提示输入**简明 ETF 网站口令**，不使用证券交易密码。只接受 HTTPS 或本机回环 HTTP，不跟随重定向。拟单复用模拟盘的目标份额、100 份取整、限价偏移（±0.2%）和费用估算。超配时只给出卖单；可卖不足或不足一手的卖出缺口会提示并阻止买入。更新已成交和资金数据后才能重新预览；不会拿预计卖出款买入。行情缺失、过期、明确停牌、持仓数据缺失或有未结委托都阻止拟单。公开行情没有权威交易状态时，这些拟单仍只是预览，不能作为信号已可在券商成交的证据。

## EMTL 只读检查：仅在获准的个人设备上

在券商确认允许后，从有权访问东方财富证券的个人设备、交互式终端运行。不要在简明 ETF 公网站点或 CI 中测试，不要把真实交易凭证交给开发者或发到聊天里。EMTL 是非官方库，不开通掘金不代表证券账户已获准使用它做程序化交易。

```powershell
python -m venv .venv-emtl
& .\.venv-emtl\Scripts\python.exe -m pip install emtl==0.3.1
$env:EM_USERNAME = '在本机填写东方财富证券资金账号'
& .\.venv-emtl\Scripts\python.exe scripts/emtl_d0.py probe --authorized-read-only
Remove-Item Env:EM_USERNAME
```

`probe` 提示输入**证券交易密码**，不会把它写进命令参数。`elapsed_ms` 分项显示登录和查询耗时；预览的 `plan_ms` 是本地算单耗时，`quote_receive_age_ms` 是行情入库到算单的时间。**这些都不是发单受理或成交耗时。** 后续如果接入经授权的真实委托，应分别记录“发单→券商确认受理”“受理→首笔成交／全部成交”，不能用 HTTP 200 代替受理，也不能在超时后盲重发。

## 开放真实委托前待确认

1. 东方财富是否允许这个账户经该接口自动委托沪深 ETF？能否先用获准的仿真/验收环境？是否允许开盘前建立会话？
2. 只接原版 D0 还是以后也接 D0I-BOND-WW？D0 用独立账户、固定额度，还是整户资产？是否有同账户的手工交易或其他策略？
3. 允许的单笔上限、单日上限、佣金和最低收费是什么？是否先限一只 ETF 和一手，由人确认？
4. 是否接受沿用 09:30 起、先卖后买？部分成交、卖不完、午休和接近收盘时，默认停等，还是需要人工批准的撤单与补单？
5. 手续费、卖出冻结和可用资金以及委托/成交状态字段，须通过脱敏样例验证；不要共享真实账号、口令、Cookie 或原始响应。未验证字段不能转换为订单。
